This release includes the changes accumulated on `main` since v1.23.2, including
persisted collection expressions and invoker functions as well as performance
and correctness fixes. Review the full changelog and the following boundaries
before upgrading.

- **Persisted contracts:** stored generated columns and CHECK expressions are
  enforced on supported TABLE mutations and recovery. Older binaries can ignore
  expression metadata and fail to enforce those rules: do not use older writers
  on databases that rely on these contracts. Keep a backup of the original
  database before enabling new persisted features; downgrade compatibility is
  not promised for them. Transactional ALTER/backfill remains unsupported.
- **Stored functions:** persisted RQL functions use invoker permissions and
  cooperative execution budgets. See [supported statements and limits](https://github.com/reddb-io/reddb/blob/v1.23.3/docs/query/stored-functions.md)
  for catalog transaction, recursion and cancellation boundaries. This release
  does not promise transactional catalog DDL or interruptible lock waits.
- **Query correctness:** graph reads and context expansion preserve logical node
  identity across retained MVCC versions, enforce collection scope and RLS, and
  hydrate visible payloads. Code that depended on stale or unauthorized results
  must adapt to the corrected behavior. Rust embedders should rebuild against
  this version and use the supported snapshot-aware query interfaces.
- **Memory and performance:** graph expansion streams physical candidates,
  retains ordered top-K neighbors and deduplicates physical edges with one last
  visible ID. In the regression, 32,768 parallel edges with a one-edge allowance
  fit within 512 KiB of available query headroom; the prior ID set exhausted that
  allowance. Cursor metadata still grows with source/alias topology, and
  identity/hydration caches with probed nodes. This is admission/result evidence,
  not process RSS, latency or throughput evidence against other databases.
- **Writes and recovery:** shared growth reservations, row-index topology guards,
  mutation admission and batched UPDATE WAL publication preserve failure,
  rollback/savepoint and recovery-tail handling. No durability setting is relaxed
  by the graph optimization. Full power-failure and competitive workload campaigns
  remain separate acceptance work.

See the [multimodel implementation ledger](https://github.com/reddb-io/reddb/blob/v1.23.3/docs/architecture/multimodel-building-block-program.md)
for delivered capabilities and remaining acceptance criteria. Linux, Windows and
macOS asset availability must be checked on this release; hosted macOS builds are
optional in the current pipeline. PyPI publication remains disabled in the
release workflow; a version bump in its manifest does not mean a wheel was published.
