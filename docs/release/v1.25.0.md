This minor closes the KV/SQL read and single-file durable-write cycle accumulated
since v1.24.15, together with the statement-snapshot and read-budget fixes already
merged on `main`.

- **KV and SQL reads:** physical key indexes and direct value projection avoid
  collection materialization for eligible point reads. Typed resolvers, index
  recovery, generation validation and cache invalidation preserve visible values
  across mutations and reopen. SQL hydration borrows ordinary rows; catalog model
  validation reuses declared metadata instead of scanning the catalog repeatedly.
- **Durable writes:** single-file KV replacement publishes the replacement,
  metadata and old-value deletion in one WAL batch. Concurrent grouped writes
  share the existing durability barriers. Overflow recovery rechecks available
  space under publication before checkpointing, and necessary checkpoints reserve
  snapshot-proportional headroom with a normal adaptive target capped at 1 MiB.
  Fresh files remain 64 KiB; larger existing regions and indivisible oversized
  operations retain their contracts. An uncertain publication failure fences the
  session until close/reopen; callers must handle the returned error.
- **MVCC and query correctness:** active statement frames retain snapshot
  horizons through query completion. VACUUM preserves versions required by
  snapshots that excluded an older writer. Simple LIMIT/OFFSET reads bound
  materialization without allocating for skipped rows or huge requested limits.
- **Configured read budgets:** oversized buffered reads return HTTP 413,
  concurrent-read saturation returns 429, and cooperative deadlines return 504.
  Classified read streams charge cumulative output before buffering; clients must
  handle stream error frames and incomplete streams. Mutation acknowledgements
  remain outside read-result limits. Zero/unset leaves each budget dimension
  unbounded. Duration/concurrency settings route point/cache reads through typed
  execution; measure staging latency and throughput before enabling them.
  Cooperative deadlines do not preempt blocking I/O or non-cooperative work, and
  output accounting does not replace deployment memory/materialization limits.

**Upgrade and compatibility:** these changes do not introduce a new storage
format or wire protocol. Existing supported clients retain their protocol
contract; no storage-format migration command is required for this cycle.
Keep a recoverable backup before upgrading and retain your configured durability
mode. Both WAL and superblock synchronization barriers remain in place.
Checkpoint reservation can increase on-disk space and WAL replay work on reopen.
Checkpointing still serializes a full snapshot; incremental checkpointing is
remaining work. This release does not qualify the pre-existing Windows
Vault/paged constructor locking limitation.

**Performance evidence:** the shared-host, fixed-order populated-store diagnostic
at eight connections measured median grouped writes/s 512.6 -> 817.8 and p99
163.67 -> 22.62 ms. Strict measured 138.0 -> 184.7 writes/s and p99
328.78 -> 209.50 ms, but its worst observed pause increased from 6.24 to 6.65 s.
All four cases completed 200,000 measured writes without request errors and
verified target/background values after SIGKILL/reopen. These are correlated
round samples without an independent-process confidence interval. They establish
neither dedicated-host capacity nor a Redis/KiviDB leadership claim. The release
also includes read-budget changes merged after that benchmark; the combined
release revision has not been rebenchmarked.
